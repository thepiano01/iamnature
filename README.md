# 나는 자연산이다 (iamnature)

산에서 채취자가 직접 캔 나물·약초·버섯을 **내 건강상태(당뇨·혈압·심장·관절 등)와 매칭**해 판매하는 직거래 플랫폼.

- Next.js 16 (App Router) · React 19 · Tailwind CSS 4 · Prisma 5 (SQLite)
- 기존 v1과 **같은 DB 스키마**(건강 항목 3개 + 배송지 4개 필드만 추가) → 기존 `prisma/dev.db` 그대로 사용 가능

## 실행

```bash
npm install
copy .env.example .env      # Windows 기준. 그다음 .env의 JWT_SECRET을 긴 임의 문자열로 바꾸세요
npx prisma db push            # DB 생성/스키마 반영 (기존 dev.db면 새 필드만 추가됨)
npm run db:seed               # 샘플 식물 14종·채취자 3명·상품 15개 (선택)
npm run dev                   # http://localhost:3000
```

샘플 계정 (비밀번호 `password123`)
- 관리자: `admin@nature.kr` — 비밀번호는 처음 seed 실행 때 **무작위로 만들어져 한 번만 화면에 출력**됩니다 (외부 공개 대비). 잊었으면 `npm run make-admin -- 내이메일`로 내 계정을 관리자로 지정하세요.
- 구매자: `buyer@nature.kr` (당뇨·혈압·관절 등록됨)
- 채취자: `seller1@nature.kr`, `seller2@nature.kr`, `seller3@nature.kr`

### 기존 v1 데이터를 쓰려면
v1의 `prisma/dev.db`와 `public/uploads/` 폴더를 이 프로젝트의 같은 위치로 복사한 뒤 `npx prisma db push` 한 번만 실행하세요.

## 화면 구성

| 경로 | 내용 |
|---|---|
| `/` | 히어로 + 건강상태 선택 → 맞춤 추천, 카테고리, 최근 채취 상품 |
| `/match` | 건강 매칭 (비회원은 URL로, 회원은 저장). 여러 항목에 겹치는 상품 우선 |
| `/products` | 검색·분류·건강 필터·정렬 |
| `/products/[id]` | 채취일/산지, 내 건강상태 매칭, 건강상태별 정보, 제철, 조리법, 주의사항, 영상 |
| `/cart` `/checkout` `/orders` | 장바구니 → 주문(재고 차감, 트랜잭션) → 주문 내역 |
| `/me` | 건강상태·배송지 수정, 채취자 전환 |
| `/sell/*` | 채취자 센터: 대시보드, 상품 등록/수정(사진 여러 장), 주문 상태 처리, 인증 서류 제출 |

## 휴대폰·외부에서 보기 (임시)

`외부공개_실행.bat`을 더블클릭하면 설치 → DB 준비 → 빌드 → 실행 → 외부 주소 생성까지 자동으로 합니다.
창에 나오는 `https://….trycloudflare.com` 주소를 휴대폰에서 열면 됩니다.
- PC와 두 개의 검은 창이 켜져 있을 때만 접속됩니다. 실행할 때마다 주소가 바뀝니다.
- 주소를 아는 누구나 접속할 수 있으니 확인용으로만 쓰세요.

## 관리자 화면 (`/admin`)

| 메뉴 | 할 수 있는 일 |
|---|---|
| 대시보드 | 이번 달 거래액·발송 대기·인증 대기·회원·판매 중 상품, 최근 14일 거래액, 처리할 일 바로가기 |
| 채취자 인증 | 영업신고증·신분증 확인 → 승인 / 반려(사유 입력, 채취자 화면에 표시) / 인증 취소 |
| 회원 관리 | 검색, 역할 변경(구매자·채취자·관리자), 이용정지(즉시 로그인 차단) |
| 상품 관리 | 숨김/다시 노출(쇼핑몰·검색·추천에서 즉시 제외), 식물 미지정·효능 미연결 상품 찾기 |
| 주문 관리 | 전체 주문 검색(주문번호·받는 분·연락처·상품명), 상태 직접 변경(취소 시 재고 복구) |
| 식물·효능 DB | 식물 추가·수정·삭제, **건강상태 연결(= 건강 매칭 기준)**, 근거 수준, 상세 설명·조리법·주의사항, 제철, 영상 |

기존 회원을 관리자로 지정하려면: `npm run make-admin -- 이메일`

## v1 대비 달라진 점

- **보안**: 로그인 정보를 localStorage에 두지 않고 HTTPOnly 쿠키 + 서버에서 DB 조회. API는 `userId`/`sellerId`를 클라이언트에서 받지 않고 세션에서 결정 (다른 판매자 주문·상품 수정 불가)
- **API 응답 통일**: `{ ok: true, ... }` / `{ ok: false, error }`
- **건강 항목 한 곳 관리**: `lib/health.ts` (심장·위·소화·기관지 추가)
- **주문**: 재고 검증·차감, 판매자별 상태 → 주문 전체 상태 자동 갱신, 취소 시 재고 복구
- **삭제 정책**: 주문 이력이 있는 상품은 삭제 대신 판매중지(주문 기록 보존)
- **업로드**: 이미지 형식·8MB 제한, 랜덤 파일명
- 읽기 화면은 서버 컴포넌트로 직접 조회 → 로딩 깜빡임 없음

## 상용 전 남은 일

- 결제(PG) 연동 — 현재는 주문 즉시 ‘주문확인’ 상태
- 신분증 등 인증 서류는 현재 `public/uploads`에 저장됨 → 비공개 저장소(S3 private 등)로 분리 필요
- DB를 PostgreSQL로 전환(`schema.prisma`의 provider 변경), 이미지 저장소를 S3 등으로 이전
- 상품 효능 문구는 식품표시광고법 검토 후 정리 (`prisma/seed.ts`, 상세 페이지 문구)
